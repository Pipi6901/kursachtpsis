# Руководство по установке (развёртыванию)

Программное средство запускается в Windows **без интегрированных сред разработки** — достаточно установить
платформы выполнения и запустить командные файлы из каталога `scripts\windows`. Руководство написано для Windows 10/11;
особенности более старых версий — в разделе 1.

## 1. Требования

| Компонент | Версия | Для чего | Проверка |
|---|---|---|---|
| Windows | 10 или 11 | — | — |
| JDK (Java Development Kit) | 17 или новее | сервер (Spring Boot), сборка | `java -version` |
| Node.js | 18 LTS или 20 LTS (проверено и на 22) | клиент (Angular 14) | `node -v` |
| Python | 3.11 или новее (проверено на 3.11 и 3.13), **рекомендуется 3.13** | интеллектуальный сервис | `py -3.13 --version` или `python --version` |
| PostgreSQL | 12 или новее (проверено на 16) | база данных `hotel` | `psql --version` |
| Google Chrome | любая актуальная | только для тестов клиента | — |

Пояснения.

* **Python**: при установке с <https://www.python.org/downloads/> отметьте «Add python.exe to PATH». Python 3.13 требует Windows 10 или новее;
  на Windows 8.1 используйте Python 3.12 — скрипты выбирают версию автоматически (3.13 → 3.12 → 3.11). Windows 8 и старше современные
  версии Python, Node.js и Java официально не поддерживают — это ограничение платформ, а не программы.
* **JDK**: подойдёт Temurin/Oracle/OpenJDK; переменная `JAVA_HOME` необязательна, если `java` и `javac` доступны из командной строки.
* **Интернет** нужен только при первой установке (Maven, npm и pip скачивают библиотеки). Работа программы интернета не требует:
  графики и шрифты модуля подключены локально.
* Свободное место: около 1,5 ГБ (библиотеки Maven, `node_modules`, окружение Python).

## 2. База данных

Модуль использует ту же базу данных `hotel`, что и исходная система (пользователь `postgres`, адрес `localhost:5432` — см.
`backend/src/main/resources/application.properties`). Существующие таблицы **не изменяются**: модуль при первом запуске сам создаёт девять
собственных таблиц с префиксами `mk_` и `fc_` и заполняет их демонстрационными данными (синтетические продажи за 196 недель,
6 каналов, 240 кампаний). Вручную ничего создавать не нужно; при желании DDL можно выполнить заранее:

```bat
psql -U postgres -d hotel -f docs\sql\forecast-schema.sql
```

Чтобы таблицы модуля создавались **пустыми** (для работы с реальными данными), задайте в `config.bat` `set "FORECAST_DEMODATA_ENABLED=false"`
до первого запуска сервера.

Если СУБД расположена не на этом компьютере или имеет другое имя базы, задайте переменные окружения сервера
`SPRING_DATASOURCE_URL` (например, `jdbc:postgresql://192.168.0.10:5432/hotel`) и `SPRING_DATASOURCE_USERNAME`
либо измените `application.properties`. Пароль задаётся `DB_PASSWORD` (см. раздел 4).

## 3. Получение проекта

```bat
git clone https://github.com/Pipi6901/kursachtpsis.git
cd kursachtpsis
git checkout claude/trusting-meitner-rrfao0
```

Либо скачайте архив ветки со страницы репозитория и распакуйте его в каталог без пробелов и кириллицы (например, `C:\hotel`).

## 4. Настройка

```bat
copy scripts\windows\config.example.bat scripts\windows\config.bat
notepad scripts\windows\config.bat
```

Задайте как минимум:

| Переменная | Что указать |
|---|---|
| `DB_PASSWORD` | пароль пользователя `postgres` вашей СУБД |
| `JWT_SECRET` | длинная случайная строка (не менее 32 символов) — подпись токенов входа |
| `ML_API_KEY` | длинный случайный ключ; **один и тот же для сервера и ML-сервиса** (скрипты передают его обоим) |
| `ML_ENCRYPTION_KEY` | парольная фраза шифрования моделей на диске |
| `BACKUP_PASSPHRASE` | парольная фраза шифрования резервных копий (необязательно: иначе спросят при создании копии) |

В значениях **не используйте** символы `& % ^ ! " < > |` — они имеют особый смысл в командной строке Windows.
Файл `config.bat` содержит секреты и в репозиторий не попадает (`.gitignore`); ограничьте к нему доступ средствами NTFS.
Без `config.bat` скрипты работают с ключами по умолчанию и предупреждают об этом: это допустимо только для знакомства с программой.

Если вы меняете `ML_ENCRYPTION_KEY` после первого запуска, ранее обученные модели станут нечитаемыми; сервер заметит их отсутствие и
обучит заново автоматически.

## 5. Первый запуск

1. **Один раз** подготовьте окружение интеллектуального сервиса (создаётся `ml-service\.venv`, ставятся библиотеки):

   ```bat
   scripts\windows\1-setup-ml.bat
   ```

2. Запустите три узла сразу — каждый откроется в своём окне:

   ```bat
   scripts\windows\start-all.bat
   ```

   или по отдельности (удобно, когда узлы на разных компьютерах): `2-start-ml.bat`, `3-start-backend.bat`, `4-start-frontend.bat`.

3. Дождитесь сообщений о запуске:

   | Окно | Признак готовности | Первый запуск |
   |---|---|---|
   | ML-сервис | `Uvicorn running on http://127.0.0.1:8001` | секунды |
   | Серверная часть | `Started DemoApplication in … seconds` | Maven скачивает библиотеки и собирает проект — несколько минут |
   | Клиентская часть | `Compiled successfully`, `Local: http://localhost:4200/` | `npm ci` ставит библиотеки — несколько минут |

   Сразу после запуска сервер создаёт таблицы модуля, загружает демонстрационные данные и **обучает две модели** (выручка и
   бронирования) — это занимает около 10 секунд после старта. Пока ML-сервис недоступен, сервер повторяет попытку каждые 30 секунд.

4. Откройте <http://localhost:4200>, войдите под учётной записью **администратора** или **менеджера** вашей системы и выберите в верхнем
   меню пункт **«Прогноз»**. Обычному пользователю (гостю) раздел недоступен.

Остановка узла — `Ctrl+C` в его окне. Перезапуск сохраняет данные: таблицы в БД, модели в `ml-service\models`.

Пересборка сервера после обновления исходного кода: `scripts\windows\3-start-backend.bat rebuild`.

## 6. Проверка работоспособности

| Проверка | Ожидаемый результат |
|---|---|
| <http://localhost:8001/health> | `{"status":"ok","version":"1.0.0",…,"encryption_enabled":true}` |
| <http://localhost:8001/docs> | интерактивное описание API интеллектуального сервиса |
| раздел «Прогноз» в браузере | график, показатели, справа вверху зелёный индикатор «Интеллектуальный сервис работает» |
| «Прогноз» → «Модель и данные» | две активные модели, ошибка (WAPE) около 5–6 % |
| остановить ML-сервис (Ctrl+C в его окне) и обновить прогноз | красный индикатор и жёлтая плашка «Упрощённый режим»; прогноз по-прежнему показывается |

## 7. Размещение узлов на разных компьютерах

Задание допускает размещение клиента, сервера и интеллектуального сервиса на разных физических узлах. Пример: сервер на `192.168.0.10`,
ML-сервис на `192.168.0.20`, браузеры — любые в сети.

**Узел ML-сервиса (`192.168.0.20`)** — в `config.bat`:

```bat
set "ML_HOST=0.0.0.0"
set "ML_API_KEY=тот-же-ключ-что-на-сервере"
```

Разрешите входящие подключения на порт 8001 в брандмауэре Windows и запустите `1-setup-ml.bat`, затем `2-start-ml.bat`. Для отдельного
узла достаточно каталога `ml-service` и каталога `scripts` (в `scripts\windows\_env.bat` корнем считается каталог на два уровня выше).

**Узел сервера (`192.168.0.10`)** — в `config.bat`:

```bat
set "ML_SERVICE_URL=http://192.168.0.20:8001"
set "ML_API_KEY=тот-же-ключ"
```

Для канала между узлами лучше включить HTTPS (раздел 8): на узле сервера задайте `USE_TLS=1` и адрес вида `https://192.168.0.20:8001`,
сертификат при этом должен быть выпущен на имя или адрес узла ML-сервиса (`make_certs.py --host 192.168.0.20`).

**Клиент**: в `frontend\src\environments\environment.ts` (разработка) и `environment.prod.ts` (промышленная сборка) укажите адрес сервера
`api: "http://192.168.0.10:8080/"`. Для промышленной сборки выполните `npm run build` и разместите содержимое `frontend\dist` на любом
веб-сервере (IIS, nginx); проверка маршрутов Angular требует перенаправления неизвестных путей на `index.html`.

## 8. HTTPS между узлами

Канал «сервер — интеллектуальный сервис» можно защитить TLS (задание, п. 3.4.1: защита передаваемых данных).

```bat
scripts\windows\enable-tls.bat
```

Скрипт создаёт в каталоге `certs\`: сертификат `ml-service.crt`, закрытый ключ `ml-service.key` и хранилище доверенных сертификатов
`ml-truststore.p12` (для него нужна утилита `keytool` из JDK). Затем добавьте в `config.bat` строку `set "USE_TLS=1"` и перезапустите ML-сервис
и сервер: сервис начнёт работать по `https://localhost:8001`, а сервер будет доверять только этому сертификату. Для другого имени узла
создайте сертификат командой `ml-service\.venv\Scripts\python scripts\make_certs.py --host имя-узла`. Закрытый ключ нигде не публикуйте
(каталог `certs\` исключён из репозитория).

Проверка: при выключенном доверии (сервер запущен без хранилища) ML-сервис оказывается «недоступным» и система работает в упрощённом режиме —
это ожидаемое поведение при неверной настройке сертификатов.

Канал «браузер — сервер» в учебной конфигурации работает по HTTP. Для эксплуатации разместите перед сервером и клиентом обратный прокси
с HTTPS (nginx, Caddy, IIS).

## 9. Резервное копирование и восстановление

Копии создаются утилитой `pg_dump` и **шифруются** (AES-256-GCM, ключ выводится из парольной фразы `BACKUP_PASSPHRASE`); незашифрованный
дамп на диск не записывается.

```bat
scripts\windows\backup-db.bat                    rem вся база hotel -> backups\hotel_full_ГГГГММДД_ЧЧММСС.sql.enc
scripts\windows\backup-db.bat --only-forecast    rem только таблицы модуля прогнозирования
```

Параметры подключения: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` (по умолчанию `localhost`, `5432`, `hotel`, `postgres`).
Если `pg_dump` не найден, добавьте `C:\Program Files\PostgreSQL\<версия>\bin` в `PATH` или задайте `PG_BIN`.

Восстановление выполняется **в новую базу данных**, рабочая база не изменяется. Перед созданием базы проверяются целостность файла и фраза:

```bat
scripts\windows\restore-db.bat backups\hotel_full_20261005_231455.sql.enc hotel_restore
```

Проверить копию без восстановления: `ml-service\.venv\Scripts\python scripts\db_backup.py verify backups\файл.sql.enc`.

Автоматическое создание копии каждую ночь (парольная фраза должна быть в `config.bat`):

```bat
schtasks /Create /SC DAILY /ST 02:00 /TN "HotelBackup" /TR "\"C:\hotel\scripts\windows\backup-db.bat\""
```

Храните копии и парольную фразу раздельно и на разных носителях: без фразы копию не прочитать, и восстановить её невозможно.
Модели интеллектуального сервиса (`ml-service\models`) копировать необязательно: после потери они обучаются заново автоматически.

## 10. Обновление и удаление модуля

**Обновление**: остановите узлы, выполните `git pull`, затем `scripts\windows\3-start-backend.bat rebuild`; при изменении
`ml-service\requirements.txt` повторите `1-setup-ml.bat`, при изменении `frontend\package.json` удалите каталог `frontend\node_modules`.
Если вы запускали более раннюю версию модуля, перед запуском новой выполните `psql -U postgres -d hotel -f docs\sql\forecast-drop.sql`
(структура таблиц моделей изменилась, а автоматическое обновление Hibernate столбцы не удаляет); данные модуля демонстрационные и создадутся заново.

**Удаление модуля**: остановите сервер, сделайте копию `backup-db.bat --only-forecast` и выполните `docs\sql\forecast-drop.sql` — будут удалены
только таблицы `mk_*` и `fc_*`. Таблицы гостиницы не затрагиваются. Затем удалите каталог `ml-service\models` и каталоги `backups`, `certs`.

## 11. Запуск тестов

```bat
scripts\windows\run-tests.bat
```

Последовательно запускаются тесты интеллектуального сервиса (pytest), эксплуатационных скриптов (pytest), сервера (JUnit; используется
встроенная база H2, **основная база не затрагивается**) и клиента (Karma, нужен Chrome). Подробности — в [testing.md](testing.md).

## 12. Типичные неполадки

| Сообщение или симптом | Причина и решение |
|---|---|
| `Не найден Python 3.11 или новее` | установите Python и отметьте «Add python.exe to PATH»; перезапустите окно командной строки |
| `Не найдена Java` / `mvnw` не запускается | установите JDK 17+, добавьте `bin` в `PATH` или задайте `JAVA_HOME` |
| сервер: `password authentication failed for user "postgres"` | неверный `DB_PASSWORD` в `config.bat` |
| сервер: `Connection refused … 5432` | не запущена служба PostgreSQL (`services.msc` → postgresql) |
| сервер не стартует: `Port 8080 was already in use` | порт занят; закройте прежний экземпляр или задайте `SERVER_PORT` (и адрес в `environment.ts`) |
| индикатор «Интеллектуальный сервис недоступен — упрощённый режим» | не запущен `2-start-ml.bat`, неверный `ML_SERVICE_URL`, или различаются `ML_API_KEY` на узлах (в журнале сервера: «отклонил ключ доступа») |
| индикатор «пауза после сбоев» | предохранитель: серия отказов сервиса; через 15 секунд после восстановления работа возобновится сама |
| сообщение «Модель отсутствует в реестре интеллектуального сервиса» | каталог моделей пуст (новый компьютер, смена `ML_ENCRYPTION_KEY`); сервер сам переобучит модели при следующем старте или по расписанию, либо нажмите «Обучить» на странице «Модель и данные» |
| «Для обучения нужно не менее 64 недель данных» | загрузите историю продаж на странице «Модель и данные» (CSV: неделя; бронирования; выручка) |
| ошибка `NOT NULL` при обучении после обновления | остались таблицы ранней версии модуля — выполните `docs\sql\forecast-drop.sql` (раздел 10) |
| `pg_dump` / `psql` не найден при создании копии | добавьте каталог `bin` PostgreSQL в `PATH` или задайте `PG_BIN` |
| русский текст в окнах отображается «кракозябрами» | в свойствах окна консоли выберите шрифт Consolas или Lucida Console; скрипты сами включают кодировку UTF-8 (`chcp 65001`) |
| `ng : File … cannot be loaded` (PowerShell) | запускайте `.bat`-файлы из `cmd.exe` либо разрешите скрипты: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
