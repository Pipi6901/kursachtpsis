# Бронирование по датам и учёт выселения

Что изменено в разделе номеров гостиничной системы (остальные разделы и данные прежние).

## Для пользователя

* **Календарь на странице номера.** Вместо поля «Количество дней» — календарь: щелчок по дню заезда, затем по дню выезда. Занятые ночи
  перечёркнуты и недоступны; выехать можно в день, когда начинается чужая бронь (ночь дня выезда не оплачивается). Ниже — срок и итоговая
  цена (цена номера × число суток). Бронировать можно и номер, занятый сегодня, если на выбранные даты он свободен.
* **Фильтр «Свободны на даты»** в списке номеров: выберите заезд и выезд — останутся только номера, свободные на все ночи периода.
  Кнопка «Сбросить» возвращает полный список; поиск по названию работает вместе с фильтром.
* **«Мои брони»** показывают даты проживания. **Выселиться** можно из подтверждённой брони, когда проживание уже началось.
* **Выселение засчитывается как состоявшееся проживание.** Бронь не удаляется, а получает статус **«Завершено»**; чек получает статус
  «Завершен». Проживание остаётся в истории гостя и попадает в статистику (доход и рейтинг номеров, длительность проживания, популярность
  кроватей, лучшие клиенты, выручка по месяцам и дням, счётчик «Завершённые» в показателях). Раньше выселение удаляло бронь и чек вместе
  с её вкладом в статистику и выручку.

## Правила

| Правило | Значение |
|---|---|
| Период проживания | полуинтервал [заезд, выезд); минимум одни сутки, максимум 100 |
| Дата заезда | не раньше сегодняшней |
| Занятость номера | пересечение с бронями в статусах «Ожидание» и «Подтверждено» (отказанные и завершённые номер не занимают) |
| Номер «свободен сейчас» | нет брони на сегодняшнюю ночь и номер не помечен занятым вручную |
| Выселение | только из подтверждённой брони, проживание по которой началось; повторное выселение, отмена и подтверждение завершённой брони отклоняются |
| Старые брони без дат | заезд берётся из даты чека, выезд — заезд плюс число суток; при выселении даты записываются в бронь |
| Отказ менеджера | гостю возвращается ровно оплаченная сумма (раньше сумма умножалась на число суток ещё раз) |

## API

| Запрос | Назначение |
|---|---|
| `POST /rooms/{id}/createRent?startDate=гггг-мм-дд&endDate=гггг-мм-дд` | бронирование на даты; параметр `days` (проживание с сегодняшнего дня) оставлен для совместимости |
| `GET /rooms/available?from=…&to=…` | номера, свободные на все ночи периода (без входа) |
| `GET /rooms/{id}/busy[?from=…&to=…]` | занятые периоды номера для календаря, без сведений о гостях (без входа) |
| `POST /reservations/{id}/moveOut` | выселение: бронь получает статус `COMPLETED` |

`GET /rooms` и `GET /rooms/{id}` возвращают `free` — свободен ли номер сегодняшней ночью.

## Изменения в базе данных

В таблицу `reservation` добавляются пустые столбцы `start_date`, `end_date`, `moved_out_at`, а ограничение допустимых значений `status`
расширяется значением `COMPLETED`. Строки броней и остальные таблицы не изменяются. Сервер выполняет это сам при запуске
(`ReservationSchemaUpgrade`); те же команды — в [sql/booking-upgrade.sql](sql/booking-upgrade.sql). Проверено на PostgreSQL 16: база,
созданная прежней версией, обновляется при первом запуске, старые брони остаются как были.

## Проверка

* сервер: `BookingCalendarIntegrationTest` — 14 проверок (пересечения и день выезда, недопустимые даты, баланс, поиск свободных номеров, занятые
  периоды без данных гостей, выселение и статистика, запрет повторных действий, старые брони без дат, возврат при отказе);
* клиент: проверки календаря и функций дат — 14 проверок;
* вручную (Chromium + PostgreSQL): фильтр по датам, выбор периода в календаре, бронирование, выселение — выручка и статистика не уменьшаются.
